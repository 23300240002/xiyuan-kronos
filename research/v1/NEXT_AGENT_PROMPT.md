### 机制解释（写论文要用）

- **模态不平衡**（arXiv 2609.10261）：融合网络里强模态占 77% 梯度，弱模态被淹没。
  这解释了为什么 xattn/GMU 都失败——它们共享一个融合算子，弱模态只能被压制。
- **MoE 为什么能行**：专家网络让梯度分流，弱模态走自己的专家，不被淹没。

### 进程管理（最大的坑）

1. **残留进程会静默抢 GPU**。本项目多次出现 2–3 个 `run_arm` 并存，
   导致单次训练从 25 分钟变成 80+ 分钟。启动新任务前务必：
   ```bash
   $SSH 'ps -eo pid,etimes,cmd | grep -E "run_arm|xy.data.l2" | grep -v grep'
   ```
2. **判断卡死不能只看"没输出"**。`grep | tail` 会缓冲。用两次采样：
   ```bash
   P=$(pgrep -f run_arm | head -1); ps -o time= -p $P; sleep 10; ps -o time= -p $P
   ```
   CPU 时间在涨就是活着。
3. **`pgrep -f 'pattern'` 会匹配自己**。`while pgrep -f 'xxx'` 是死循环。
4. **不要给监控加"自动重启"**。曾经因此造出 3 个重复队列并行跑不同 seed，
   浪费 50 分钟 GPU。监控只做只读告警。
5. **`setsid nohup ... & disown` 偶发不生效**。启动后必须验证日志文件真的被创建。

### 评估与目录

6. **`test_eval` 必须传 `--match`**。同一个 arm/seed 有多个版本目录时，
   `sorted(glob)[0]` 会选到最早的，用错权重算出**看起来正常但完全错误**的结果。
7. **单 token 的 `std` 恒为 0**。任何"末点+均值+标准差"池化都要检查序列长度，
   否则输入有 1/3 是退化值（`late_ens` 因此 IC −0.0338）。

### 口径一致性

8. **跨标签的 val IC 不可直接比**。raw 标签和截面 z-score 标签的 Pearson IC 口径不同，
   要比就用测试段对原始收益算的指标。
9. **stride 决定样本量**。5min 用 40，15min 用 13，1min 用 200 才能保证每 epoch 样本量相当。
10. **L2 覆盖只有 2.7% 的时间点**。涉及 L2 的模型要按微观侧的有效性过滤窗口，
    否则 NaN 会污染训练。
