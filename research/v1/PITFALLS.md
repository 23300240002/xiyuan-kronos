## A. 统计效力与结论强度（最容易被忽略）

这一组不涉及操作，但**直接决定结论能不能写进论文**。

### A1. 测试段只有 3 天（5min）/ 20,638 个窗口（L2）

IC 绝对值小（0.001–0.07），**3 天的测试集不足以支撑强结论**。
任何结论必须标注「测试段天数 + 窗口数」。

### A2. val→test 衰减普遍 17%，最极端一例 41% → 3.5%

| 案例 | 验证段 ΔIC | 测试段 ΔIC | 衰减 |
|---|---|---|---|
| arm-3 vs arm-1（5min，seed 0） | +0.01323（41%） | +0.00161（3.5%） | **−91%** |
| arm-1 自身（3 种子均值） | +0.04576 | +0.03791 | −17% |

**含义**：验证段上看到的"提升"到测试段会大幅缩水，甚至消失。
**只报验证段结果的结论一律不可信**。

### A3. 种子方差可达 ±0.021

截面模型的 RankIC 逐种子：+0.0698 / +0.0200 / +0.0337（std ±0.021）。
**单种子结论不可用**，必须 3 种子 + 同种子配对比较。

### A4. arm-2 的"异常稳定"要警惕

arm-2（仅 M1）的 std 只有 **0.00032**，是 arm-1 的 1/10。
这不是好信号——可能是模型输出接近常数（塌缩），
需要检查预测值的方差，而不是只看 IC 均值。

### A5. 早期报告的配对检验不完整

`reports/06_三臂消融.md` 里的 ΔIC 是用"arm-3 三种子均值 − arm-1 三种子均值"算的，
**不是配对比较**。严格做法是逐种子相减再取均值与 t 值（`reports/09` 已改）。

## B. 数据与口径

### B1. 我们不是 Kronos 论文的同规模复现

Kronos 原论文用 **Kronos_S/B/L 三档全量微调 + 自有大规模数据**；
本项目只用**冻结的 kronos_small（24.7M 总参 / 4.1M 主干）**。
**任何与论文数字的对比都要说明这一点**，否则是误导。

### B2. 日频段样本量不足

672 个交易日对日频预测（H=24 日）偏少，这是日频结果弱（val IC 0.002–0.028）的主因之一。
已转向 5min 频段。

### B3. L2 的 18 天是"分散"的，lookback 被压在 24

5min 一天 48 根，窗口不能跨缺失日期。
- 18 天分散 → 每窗口困在单日内 → lookback ≤ 24（半天）
- **这是 L2 实验与 K 线实验口径不可比的根源**（K 线用 240 = 5 天）
- 已下载 30 天连续块（20241008–20241118）解决此问题，解析中

### B4. L2 覆盖率只有 2.7% 的时间点

涉及 L2 的模型必须按微观侧有效性过滤窗口，否则 NaN 污染训练。
过滤后样本量骤降，要重新核对训练/测试样本数。

### B5. 跨标签的 val IC 不可直接比

raw 标签与截面 z-score 标签的 Pearson IC 口径不同。
要比就统一用**测试段对原始收益**算的指标（Spearman 保序，Pearson 不保）。

### B6. stride 决定每 epoch 样本量

| 频段 | stride | 理由 |
|---|---|---|
| 5min | 40 | 基准 |
| 15min | 13 | 1/3 的 bar 数，stride 也取 1/3 |
| 1min | 200 | 5 倍 bar 数，stride 取 5 倍 |

**不按此对齐，多频率对比就不是"频率"的差异，而是"样本量"的差异。**

### B7. 归档里混有大量非股票标的

单个日期的行情表数量：7,275 / 29,145 / 58,352 不等，而票池只有 **500 只**。
必须用 `--pool-from runs/tensor/5min` 过滤（**14.6 倍加速**）。

### B8. 原始十档曾被删除，重走 DeepLOB 路线要重下 74.5GB

当时为省磁盘删了 7z，只剩派生 7 列。**教训：派生特征要留原始列。**
新解析（`parsed_30d`）已带 `--keep-raw`，含 40 个无量纲原始档位。

## C. 环境与进程操作（踩坑最多的一类）

### C1. 残留进程会静默抢 GPU

本项目多次出现 2–3 个 `run_arm` 并存，单次训练从 25 分钟变 80+ 分钟。
**启动任何任务前先查**：
```bash
ps -eo pid,etimes,cmd | grep -E "run_arm|xy.data.l2|test_eval" | grep -v grep
```

### C2. 判断卡死不能只看"没输出"

`grep | tail` 会缓冲，长任务可能几十分钟没有输出但正常在跑。
**用两次采样看 CPU 时间**：
```bash
P=$(pgrep -f run_arm | head -1); ps -o time= -p $P; sleep 10; ps -o time= -p $P
```
时间在涨 = 活着。

### C3. `pgrep -f 'pattern'` 会匹配自己

`while pgrep -f 'xxx'; do ...; done` 是**死循环**（shell 自己的命令行含该 pattern）。
改用 PID 或加 `grep -v $$`。

### C4. 不要给监控加"自动重启"

曾因监控误判"队列异常"而自动重启，造出 **3 个重复队列并行跑不同 seed**，
浪费 50 分钟 GPU，还让同一个 seed 跑了两遍。
**监控只做只读告警，重启由人判断。**

### C5. `setsid nohup ... & disown` 偶发不生效

启动后**必须验证日志文件真的被创建**：
```bash
setsid nohup bash x.sh > runs/x.log 2>&1 < /dev/null & disown
sleep 20 && ls -la runs/x.log     # 不存在就是没起来
```

### C6. 长任务日志必须直写，不要过 grep

`cmd 2>&1 | grep -E '...' | tail -2` 会把输出全缓冲到进程结束，
期间完全看不到 epoch 进度，无法判断是否卡死。

### C7. SSH 复用连接失效会中断正在跑的命令

长命令（如 `sleep 300 && ...`）期间连接断了会 SIGTERM 整个远端命令。
**长任务一律 `setsid` 分离**，不要依赖 ssh 会话存活。

## D. 代码陷阱

### D1. `test_eval` 必须传 `--match`

同一个 `arm{freq}s{seed}` 有多个版本目录（原始/rank/xsec_z/sde…）时，
`sorted(glob(...))[0]` 会选到**字母序最靠前**的（通常是最老的）。
不发现的话，新跑的臂会被拿**旧权重**重算，得到**看起来正常但完全错误**的结果。

### D2. 单 token 的 `std` 恒为 0

任何「末点 + 尾部均值 + 尾部标准差」池化，都要检查序列长度。
`late_ens` 第一版把 `[B,1,d]` 直接池化，第三段恒为 0（甚至 NaN），
微观头输入 1/3 退化 → IC −0.0338（比什么都不做还差）。

### D3. 多进程 Pool 崩溃抛 BrokenPipeError

父进程死时子进程还在写管道。**续跑必须跳过已完成部分**，
否则重复劳动。解析已因此中断两次。

### D4. 变量遮蔽

`pool = set(codes)` 与 `with mp.Pool(...) as pool:` 同名会互相覆盖。
multiprocessing 的变量名已改为 `mp_pool`。

### D5. 逐时刻融合要广播微观 token

`MicroEncoder` 输出 `[B,1,d]`，与 `h [B,T,d]` 做逐时刻融合前必须
`expand(-1, T, -1)`，否则 size mismatch。

### D6. 融合模式与 Head 输入维度要配套

- `concat`：输出 `[B, 2d]` 向量，Head 吃 2d
- `gmu/film/moe2/xattn/gate_res`：保留时间维，Head 吃 3d
- `late_ens`：两个独立头，微观侧需 `proj_m2k` 从 128 升到 d_model

## E. 已有结论的适用边界

**写论文时必须带上这些限定词**：

| 结论 | 适用边界 |
|---|---|
| 融合无增量（5min） | 仅限 M1 成交流通道 + L=240 + 672 天 |
| L2 单模态有信号 | 仅限 18 天分散 + L=24（半天上下文） |
| 交叉注意力有害 | 仅限 L=24 短序列（注意力只有 24 个 key，噪声占比过高） |
| **MoE 产生增量** | **仅限 L2 + L=24，M1 通道验证中** |
| 截面注意力提升 RankIC 2.9 倍 | 训练 stride=80（一半样本），**严格公平性待验证** |
| 截面标签对独立模型有害 | 3 种子，val IC 口径，测试段未评估 |
| Rank 损失与 MSE 持平 | 4 个结果含 1 个重复，pairwise 在 batch=128 下信号太稀疏 |
